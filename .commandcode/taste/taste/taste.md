# Taste
- Prefers source-revision validation where CI rebuilds the gem and reports the actual CI-built SHA-256; does not assume CI SHA must equal local reference SHA unless byte reproducibility is established. Confidence: 0.95
- Insists on black-box Lab discipline: fix invalid scenario setup rather than modifying product source, monkey-patching analyzers, faking AnalyzerResult/JSON, disabling required analyzers, or weakening expected INCOMPLETE/FAIL to PASS. Confidence: 0.92
- Prefers minimal realistic target-project mutations to make a required analyzer genuinely unavailable — e.g., removing bundler-audit from Gemfile/bundle and updating Gemfile.lock consistently so `bundle exec bundler-audit` provably fails. Confidence: 0.88
- Requires deterministic scenario preconditions that prove the analyzer is actually unavailable BEFORE product execution and fail as LAB SCENARIO SETUP (infrastructure failure, not product failure) if the analyzer is still executable; avoids generalizing into a large scenario framework. Confidence: 0.90
- Treats expected FAIL and INCOMPLETE as valid green CI when they match the scenario Oracle (e.g., FAIL/complete/fail/exit 1, INCOMPLETE/incomplete/not_evaluated/exit 2); expects oracle expectations to be preserved, not weakened to paper over defects. Confidence: 0.94
- Prefers safe branch synchronization via rebase onto updated main with --force-with-lease where Lab already uses rebasing, preserving each scenario's unique mutation and not closing/recreating PRs. Confidence: 0.85
- Expects full external oracle evidence after changes: wait for all PR workflows and collect matrix table with PR, Scenario ID, Head SHA, candidate revision, CI-built SHA, expected/actual gate, completion_status, policy_status, exit, Oracle match, workflow conclusion; do not publish candidate on validation success without explicit instruction. Confidence: 0.87
- Prefers to keep operational/security and closeout scenarios (RVLAB-13..21) on the existing lab operational runner/dedicated workflow and to reuse existing scenario definitions, reserving PR workflows for the core matrix (RVLAB-01..12) and avoiding creation of duplicate scenarios or unnecessary long-lived PRs for appearance. Confidence: 0.92
- Validates policy-cheat, waiver-cheat, and baseline-cheat detection via the product's existing Repair::Verifier / verification_boundary_changed contract (build_repair_packet → synthetic source edit → verify_repair) rather than inventing new Lab anti-cheat mechanisms; expects boundary mutation to be surfaced as verification_boundary_changed, not as successful repair. Confidence: 0.90
- Requires MCP proofs to be black-box against the installed gem via a real stdio client without product modification or AI: path containment must return isError:true with code invalid_arguments and no external content leakage for traversal, absolute, and symlink escapes while valid inside-root paths are accepted; cache freshness must be proven for dirty->dirtier same-file edits and untracked file content changes with unchanged HEAD and same Git status category, without commit or server restart, and verify_repair must also use fresh state. Confidence: 0.88
- Requires fresh no_new_debt bootstrap to be explicit: missing baseline with existing Findings must be INCOMPLETE/incomplete/not_evaluated baseline_required exit 2 (not silent PASS or strict, no auto-create), baseline create must succeed from that state, then normal no_new_debt semantics apply where existing debt is non-blocking and new regressions still FAIL. Confidence: 0.86
- Expects AI/privacy and MCP response-bounds smokes to be offline and deterministic: localhost HTTP stub only with zero remote requests when AI is disabled or during railverdict check, and large verify responses must signal findings_truncated with total/returned counts or bounded response_too_large so truncation is never mistaken for complete results. Confidence: 0.85
